# /pr - プルリクエスト作成

`/pr` が実行されたら、現在のブランチの変更内容をもとにGitHubのプルリクエストを作成する。

## 手順

1. `git status` / `git diff` / ベースブランチ(通常 `main`)との差分・コミットログを確認し、変更内容を把握する。
2. 現在のブランチがリモートに存在するか確認する。存在しなければ `git push -u origin <branch>` が必要になる旨をユーザーに伝えてから実行する(共有状態を変更するため無断で実行しない)。
3. 本文のフォーマットを決める。
   - ユーザーが `/pr` 実行時にフォーマットや記載内容を指定した場合は、それに従う。
   - 指定がない場合はリポジトリ直下の `pull_request_template.md` を読み込み、その見出し構成(例: 変更内容 / 完了条件 / 補足事項)をそのまま使う。
   - `pull_request_template.md` が見つからない場合のみ `.github/PULL_REQUEST_TEMPLATE.md` を代わりに使う。
4. 各見出しの内容を、実際の差分・コミット・関連Issueから埋める。
   - ブランチ名が `feature/<issue番号>` の形式なら、対応するIssue番号を本文に含める(例: `Closes #<issue番号>`)。
   - 空欄のまま残さず、diffやコミットメッセージから要約して埋める。
5. PRを作成する前に、タイトルと本文をユーザーに提示して確認を取る(PR作成はチームに見える共有アクションのため)。
6. 承認後、`gh pr create --title "..." --body "$(cat <<'EOF' ... EOF)" --base main` を実行する。ドラフトや別ベースブランチの指定があればオプションに反映する。
7. 作成されたPRのURLをユーザーに報告する。
